  • 문제/배경: 2025-03-17 약사웹 도매몰이 외부 몰에서 자사몰로 옮겨졌지만, 도매 제휴 약국이 아니면 도매 메뉴를 쓸 수 없었고 상세를 거쳐야만 담을 수 있었음. 약품 도매 이용 허들을 낮추는 것이 목표(릴리즈노트).
  • 기여:
    • 가입 관문을 결제 시점 약관 동의로 옮겨 비제휴 약국도 둘러보고 담게 함(동의 후 곧바로 주문하는 원룩 흐름 제안).
    • 리스트·랭킹·주문 상세에서 바로 담기 모달, 최근 구매·관련 상품·함께 주문하기 좋은 상품, 검색바 고정과 최근·추천 검색어를 FE 단독으로 냄(2025-05-07).

    • 월 도매 매출 9.4억 → 12.1억 (+28%, 2025년 4월 → 5월). 같은 시기 자사몰 전환으로 구매 약국 수도 375 → 506곳으로 늘어(약국당 결제액은 −9%), 퍼널 개편 단독 효과로 분리하지는 않음.
  • 한계: 2025-04-21 첫 배포에서 필수 약관 설정 때문에 전 약사에게 약관 동의 모달이 떠 두 번 롤백하고 같은 날 재배포함.

    • 기여: 조제 수락·거절 직후 결과 페이지의 도매 추천 상품(거절은 비대면 처방 상위, 수락은 최저가 상품에서 4개), 조제리스트 노출 뱃지, LNB 도매 메뉴 툴팁을 붙이고, 운영이 문구와 노출을 직접 바꾸는 CS 어드민 약국 도매 툴팁 관리 화면을 만듦. 결과 페이지 클릭 로그 6종은 배포 전에 기획·디자인과 맞춤.
    • 성과: (PM·디자이너 집계, 배포 후 약 2개월) 조제 수락 결과 페이지 진입 세션 대비 장바구니 약 5%, 바로구매 약 8%. 디자이너 요약은 “전환율 자체는 정체”였고 대조군이 없어 효과는 주장하지 않음.
  • 2025.Q4 — 의사웹 LNB 툴팁 이식:
    • 문제/배경: 의사 회원의 도매 서비스 인지도가 낮고 구매 전환율이 정체됨.
    • 기여: 약사웹 LNB 도매 툴팁(2025.Q3 본인 구현)을 의사웹 LNB 도매 메뉴 옆에 이식하고, CS 어드민에 의사 도매 툴팁 관리를 붙여 운영팀이 문구를 직접 켜고 끄게 함.
    • 성과: 툴팁 배포(2025-11-24) 전후 15일 의사 도매 주문 7 → 23건(3.3배), 일평균 결제액 34.8만 → 222.8만 원(6.4배). 같은 기간 약사 도매(대조)는 −2.4%. LNB 클릭 로그가 없고 배포 전 표본이 7건이라 툴팁 효과로 귀속하지 않음.

4. 결제 시스템 개편 (토스 PG 전환 FE · 토스페이 간편결제)

  • 문제/배경: 기존 PG사의 높은 수수료 문제 해결을 위해 토스페이먼츠로의 전환이 필요했으나, 카드 재등록 과정에서 유저 이탈이 우려됨.
  • 기여:
    • 토스 PG 전환 2단계의 FE를 맡아 카드 등록을 BFF 뮤테이션으로 바꾸고 첫 등록 500P 혜택·카드 재등록 안내를 진료 신청서에 붙임. 앱 선배포가 필요하다는 배포 순서 리스크를 짚어 이벤트 시작을 하루 늦춤.
    • BroadcastChannel API를 활용하여 웹뷰(카드등록)와 웹뷰(결제 또는 카드관리) 간의 실시간 데이터 동기화 구현, 카드 등록 이벤트 포인트 지급 안내.

10. 다이어트 원외처방 지도: 총액 표기와 가격 근거 A/B 연작

  • 메타: 2026.08–09 · FE 단독(실험 설계·구현·판정·정리), PO·디자인·BE·법무 협업 · Next.js, GrowthBook(Bayesian), GA4/BigQuery
  • 문제/배경: 원외처방은 결제 전까지 진료비와 약제비를 합친 총액을 알 수 없어 이탈한다는 가설이 있었음. 지도에는 진료비만 보였고, “원외가 최저가”라는 전제도 실측과 반대였음(위고비는 원내가 17~46만 원 저렴).
  • 실패에서 시작: “지도에 총액을 표기하자”는 제가 낸 안이었고, 이를 포함한 변경 5가지를 8/19 한 번에 배포한 뒤 원외 방문예약률이 23.4% → 22.1%(배포 전 3주 대비)로 떨어짐. 저는 “모수가 적으니 더 지켜보자”였고 조치를 이끈 건 팀 리드였음. 롤백하면 원인을 모른 채 기획~배포 2~3주가 사라지므로 “더 나빠지면 즉시 되돌린다”를 조건으로 요소를 하나씩 떼어 A/B 4번(8일)을 돌려 원인(기본으로 켜 둔 약제비 토글)을 찾았고, 8/27 방문예약률 24.1% 로 배포 전보다 높게 회복함.
  • 전사 타운홀 회고 (2026.08): 이 과정을 “우리는 유저를 몰랐다”는 실패담으로 직접 발표. 교훈은 유저에 대한 확신을 갖지 말 것, 변경은 작게 하나씩, goal 은 처치에서 가까운 퍼널로, 판정했다고 기록할 것. 이후 3파티 실험은 한 번에 하나씩 바꾸는 기준으로 설계함(통합검색에서 요소를 여러 개 넣는 안을 홀드).
  • 핵심 판단:
    • 법무 검토(“추천이 아니라 단순 가격 표기”, 조제비 → 약제비 용어)를 표기 규칙으로 삼음. 클러스터마다 중앙값을 보여 주는 안은 서버 비용이 커서, 클러스터 제거를 제안해 BE 작업을 0으로 만듦.
    • “처치를 본 사람만 분모에 넣는다”: 노출 시점을 카드 오픈 → 지도 진입으로 옮기고, 대조군까지 바뀐 구간은 seed 를 유지한 채 봉인·재시작.
    • 판정 근거를 숨기지 않음: 처치 이전 단계 지표가 오른 결과는 집계 아티팩트로 판정해 성과에서 제외하고, goal 이 아닌 보조 지표로 채택한 경우 그 한계를 결과 기록에 명시.
  • 기여:
    • 한 달간 A/B 5건(총액 표기 · 가격 위계 · 인근 약국 가격 근거 · 마커 표기 단위 · 근거 상시 노출)과 약국찾기 → 원외 지도 유입 배너를 설계·구현·판정하고 실험마다 코드 정리 PR 을 분리.
    • 카드 총액과 약국 가격 리스트가 같은 값을 쓰도록 이상치 하한 가드를 공용 모듈로 추출.
    • 유입원 파라미터를 필수 인자로 만든 순수 함수로 계측 누락을 컴파일 단계에서 차단.
  • 성과:
    • 인근 약국 가격 근거 노출 A/B: 진료신청 완료율 12.12% → 13.36% (상대 +10.2%, B안이 나을 확률 97%, n=11,349 · 보조 지표 기준 채택). B군 중 약국 가격 리스트를 실제로 펼친 사람은 9% 라 효과 크기는 보수적으로 읽음.
    • 같은 기제의 상시 노출 A/B 에서 +4.46% 로 방향 재현, 반대로 한 걸음 더 나간 “기본 펼침”은 지도 탐색을 잠식해 기각. 세 실험을 이어 읽어 “보여 주기와 펼쳐 두기는 다르다”는 결론.
    • 후킹 배너 배포 3시간 유저 CTR 22.6%, 배너 클릭 → 원외 지도 도달 98.4%.

11. 의사웹 진료보드: 30초 자동 갱신(직접 발의) → 취소 건 노출 (FE+BE)

    • 기여: 4개 앱 에러 로그 진입점에서 RUM 에러를 함께 기록(SDK 예외 전파 우려 3건은 SDK 소스로 기각), 의사웹 RUM 에 의사 정보 부착, 5개 앱 로그 메시지에 실제 에러 문구. 반영된 필터를 조회로 검증하다 유저앱 환경 태그가 달라 보존이 0건이 되는 조건을 잡아 복구.
    • 성과: 의사웹 RUM 세션의 의사 식별 0% → 98.9%. 로그 메시지 새 형식이 의사웹·약사웹 에러 로그 대부분에 적용. 보존 세션·세션 id 누락률 변화는 재측정 예정.

  • iOS 27 에서만 검색창 키보드가 안 뜸 (2026.Q4): 최소 재현 앱으로 실기기를 측정해 “사용자 조작 없는 focus 에는 WebKit 이 포커스 이벤트를 보내지 않는다”를 확정하고 네이티브 변경 없이 JS 로 해결(CodePush). 화면 밀림은 로딩 스피너가 웹뷰 높이를 0 으로 누르는 것을 측정해 오버레이로 바꿈.
  • 안드로이드 검색 결과에서 뒤로가기가 홈으로 나감 (2026.Q4): react-native-webview 13.16 안드로이드가 같은 문서의 replaceState 에도 페이지 로드 시작 이벤트를 보내는 것이 원인. 새 문서마다 실행되는 스크립트의 메시지로만 상태를 초기화.
  • 의사가 끈 예방접종이 계속 예약됨 (온콜, BE, 2026.Q4): “OFF 했는데 예약이 들어온다” CS 를 앱 예약 경로까지 따라가, ON/OFF 는 다른 테이블에 저장되는데 노출 쿼리는 가격 행만 보고 OFF 시 가격 행이 남는 것을 확인. “작년 가격 = 외부 기준가 행” 가설은 운영 실측으로 버림. FE 에서 거르는 안은 응답에 ON/OFF 필드가 없고 페이지네이션·평균가가 서버에 있어 기각하고 서버 노출 쿼리를 고침. 문의 온 7곳이 아니라 전수로 잔재 133행을 정리. 데브존 검증 중 앱이 탭을 바꿔도 첫 접종 카테고리를 보내는 탓에 내 첫 구현이 다른 접종까지 숨기던 버그를 잡음. 이후 3주 같은 유형 문의 0건(사내 채널 검색 기준).
